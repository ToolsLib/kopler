# Kopler 0.1.2

Kopler can now check GitHub Releases for updates and install signed updates from Settings.

- Automatically checks on startup and every six hours without interrupting capture. A small “Update available” button opens Settings when a newer version is found.
- Check manually in Settings, read the release notes, or choose **Install and restart**. Downloads show progress, and the package signature and signed version are verified before installation.
- Pending notes, drafts, and edits are saved before updating. A failed save, download, or verification leaves the current app and your work available for retry.
- Automatic checks can be disabled in Settings. Windows installations, macOS apps, and Linux AppImages support in-app installation; package-managed Linux builds offer a release download instead.
- Settings now displays the actual installed version.

## Updating from 0.1.1 or earlier

Install this version manually once: older versions do not contain the updater. Quit Kopler from Settings or the tray, then install the new Windows setup executable, macOS DMG, or Linux package. Subsequent versions can be installed from the app. Your existing local data directory is retained.

## Downloads

| System | Manual installation |
| --- | --- |
| Windows x64 | `Kopler_0.1.2_windows_x64-setup.exe` |
| macOS 14+ — Apple Silicon and Intel | `Kopler_0.1.2_macos_universal.dmg` |
| Linux x64 | `Kopler_0.1.2_linux_x64.AppImage` or `Kopler_0.1.2_linux_x64.deb` |

The release also contains the signed macOS updater archive, three `.sig` files, `latest.json`, and `SHA256SUMS.txt`. Updater files and manual build candidates use GitHub Release storage, without Actions artifacts.

## Platform status

Updater signatures are separate from operating-system publisher signing: Windows packages remain unsigned, and macOS builds are ad-hoc signed and not notarized. macOS native interaction testing and a full update installation between two published updater-enabled versions remain pending. Linux self-updates require a writable AppImage; use your package manager or the DEB for other installations. Updates contact public GitHub Releases; notes and drafts remain local.
